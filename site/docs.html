Getting started

Install

Install the command from a checkout of the repository. It requires Python 3.10+ and Typst on your PATH; FFmpeg is needed only for video.

uv tool install .

pipx install . works too. Without installing, run python3 bin/glissade.py wherever this page writes glissade.

Write a deck

A Glissade deck is an ordinary Typst document with a deck show rule and one or more slide blocks. Inside a slide, animation state is declared with primitives such as init, animate, and cut, then read with a("name") inside context.

#import "@preview/glissade:0.1.0": *
#set page(width: 128mm, height: 96mm)
#show: deck.with(fps: 12)

#slide(title: "A first animation")[
  #init(width: 1cm)
  #animate(width: 8cm)
  #wait(duration: .45)
  #cut(loop: true)

  #context [
    #rect(width: a("width"), height: 1cm)
  ]
]

The animation finishes automatically when the slide block closes. For ordinary Typst/PDF rendering, a slide-level fps overrides the deck FPS. The html, dev, and video commands instead use their command-line --fps value for every slide, defaulting to 30.

Preview and export

Use dev while authoring and html when you want a portable presentation. Every option is listed under Export and preview.

# Live editor, rebuilt on every save
glissade slides.typ dev

# One self-contained HTML presentation
glissade slides.typ html --fps 24

Use Glissade inside Touying

Touying can own slide layout, themes, and incremental reveals while Glissade supplies continuous animation segments. Bind Touying’s public touying-fn-wrapper once and place the resulting function between native pause, uncover, or only steps.

#import "@preview/touying:0.7.3": *
#import themes.simple: *
#import "@preview/glissade:0.1.0" as glissade

#show: simple-theme.with(aspect-ratio: "16-9")
#let glissade-animation = glissade.touying(
  touying-fn-wrapper,
  fps: 12,
)

Another Touying reveal

The html and dev commands detect Touying metadata automatically. Native Touying subslides become presenter cuts; subslides reserved by touying-animation play continuously between those cuts. Glissade does not replace or wrap Touying’s jump, pause, or cover functions.

Do not add #show: glissade.deck to a Touying document: both functions are document-level renderers.

glissade.touying sets the default FPS for every embedded animation in an ordinary typst compile. Pass fps directly to one glissade-animation call to override it locally. Glissade’s html, dev, and video commands use their command-line --fps value instead.

Animation state and interpolation

State names are local to a slide. Declare an initial value with init, change it with an animation primitive, and read it with a("name") inside context. A state must keep a compatible type for its entire timeline.

Glissade interpolates integers, floats, lengths, ratios, angles, arrays, and functions whose result has a supported type. Arrays must keep compatible element types. Content is held at its previous value until the transition completes; use glissade-morph when content should transform visually in the browser.

#init(x: 0pt, opacity: 20%, samples: (0.0, 1.0))
#animate(
  x: 8cm,
  opacity: 100%,
  samples: (1.0, 0.0),
  duration: .8,
)

#context {
  place(dx: a("x"))[
    #text(fill: black.transparentize(100% - a("opacity")))[Hello]
  ]
}

If a state is first introduced by animate, Glissade infers a zero-like starting value. Explicit init is preferable when that inferred value would be unclear.

Animation primitive reference

A slide’s timeline is a sequence of blocks. Each primitive either opens a block, adds to the current one, or marks its end.

PrimitiveEffect on the timeline
initDeclares the starting value of one or more states.
animateStarts a new timeline block and interpolates states to new values.
meanwhilePlaces another animation at the start of the current block.
thenAppends an animation after the current block’s existing content.
waitExtends a block without changing state.
cutCreates a presenter boundary at the end of the current block.
createA convenience for content state: initializes it as empty and animates it in with draw-border-then-fill by default.
 
#animate(
  x: 8cm,
  hold: .2,        // delay before interpolation
  duration: .8,    // interpolation time
  dwell: .3,       // hold the final value
  transition: smooth,
)
#meanwhile(opacity: 100%, duration: .8)
#then(color: blue, duration: .4)
#wait(duration: .5)
#cut(loop: false)

Timing

animate, meanwhile, then, and create share the same timing arguments, all in seconds.

ArgumentDefaultMeaning
hold0Delay before interpolation starts.
duration1Interpolation time. wait takes this argument too.
dwell0Time the final value is held before the block continues.
transition"smooth"The interpolation curve, as a function or its name. See transitions.

Pass block to animate or wait only when you need explicit block placement. Most decks are clearer when they rely on the implicit sequence.

Animate a value

init gives a variable its starting value. animate creates the next timeline block and interpolates that variable to a new value. Use a("width") from a Typst context to read the value for the current frame.

animate-width.typvalue state
#init(width: 42pt)
#animate(width: 220pt, duration: 1.1)
#wait(duration: .45)
#cut(loop: true)

#context [
  #rect(
    width: a("width"),
    height: 34pt,
    radius: 5pt,
    fill: accent,
  )
]

Coordinate variables with meanwhile

meanwhile adds another variable animation to the current block. It is useful when several visual properties should change together: position and opacity, scale and color, or multiple diagram coordinates.

meanwhile.typsame block
#init(x: 20pt, opacity: 20%)
#animate(x: 210pt, duration: 1.2)
#meanwhile(opacity: 100%, duration: 1.2)
#wait(duration: .45)
#cut(loop: true)

#context [
  #place(dx: a("x"), dy: 32pt)[
    #circle(
      radius: 23pt,
      fill: accent.transparentize(100% - a("opacity")),

Sequence steps with then, wait, and cut

then appends an animation after the current block, wait holds state for a duration, and cut creates a playback boundary. In the browser, advancing moves through cuts before moving to the next slide.

then-wait-cut.typpresenter boundary
#init(step: 0)
#animate(step: 1, duration: .45)
#then(step: 2, duration: .45)
#wait(duration: .35)
#then(step: 3, duration: .45)
#wait(duration: .55)
#cut(loop: true)

#context [
  // Render each box as active when step reaches it.
]

Loop a segment

Pass loop: true to cut when a segment should keep playing until the presenter advances. This is useful for ambient motion on title slides, waiting screens, or diagrams that should stay alive while you talk.

A loop normally repeats everything since the previous cut. Pass a number instead, as in cut(loop: 2), when a longer animation ends in a cycle: the whole segment plays once, then only its last two animate blocks repeat.

loop.typlooping cut
#init(width: 48pt)
#animate(width: 230pt, duration: .9)
#animate(width: 48pt, duration: .9)
#wait(duration: .35)
#cut(loop: true)

#context [
  #rect(
    width: a("width"),
    height: 40pt,
    radius: 20pt,
    fill: rgb("#19a974"),
  )
]

Pick a transition function

Animation primitives accept transition. Built-ins include linear, smooth, quad, cubic, quart, sin, circ, and the cubic ease-in, ease-out and ease-in-out. smooth stays almost still at both ends, which suits long moves; ease-in-out is gentler and reads better on moves shorter than a second. Each built-in can also be named by a string, such as transition: "ease-in-out". You can also provide a custom function from [0, 1] to [0, 1].

transitions.typcurves
#init(linear-x: 0pt, smooth-x: 0pt, sin-x: 0pt)
#animate(linear-x: 200pt, duration: 1.2, transition: linear)
#meanwhile(smooth-x: 200pt, duration: 1.2, transition: smooth)
#meanwhile(sin-x: 200pt, duration: 1.2, transition: sin)
#wait(duration: .45)
#cut(loop: true)

#context [
  #row("linear", 28pt, a("linear-x"), blue)
  #row("smooth", 78pt, a("smooth-x"), green)
  #row("sin", 128pt, a("sin-x"), purple)
]

Morph formulas by marking parts

Wrap a formula in formula(...), mark the pieces that should be tracked with part, then render the state with glissade-morph. Matching parts move between frames, while unmatched pieces can fade in or out.

A compound part such as part(a^2) or part(x+1) moves as a whole: each of its glyphs is tracked under a key derived from the part's key (…/base, …/t for the exponent). Pass key: "c" to match parts whose bodies differ, for example part(c^2, key: "c") in one state and part(c, key: "c/base") in the next.

formula-morph.typsemantic SVG
#init(eq: formula($part(a) part(=) part(b)$))
#animate(
  eq: formula($part(a) / part(c) part(=) part(b) / part(c)$),
  duration: 1.1,
)
#wait(duration: .45)
#cut(loop: true)

#align(center)[
  #context [
    #text(size: 34pt)[#glissade-morph("eq")]
  ]
]

Create content with draw-border-then-fill

create introduces content from an empty state. By default it attaches the draw-border-then-fill morph effect, so the browser runtime can draw the shape before filling it.

create-reveal.typcontent reveal
#create(card: [
  #rect(
    width: 230pt,
    height: 92pt,
    radius: 8pt,
    fill: rgb("#d8e9df"),
    stroke: 1pt + rgb("#246b61"),
  )[New idea]
], duration: 1.5)
#wait(duration: .45)
#cut(loop: true)

#align(center)[
  #context [#glissade-morph("card")]
]

Use slide metadata

slide accepts an explicit id, a browser overview title, autoplay, and an fps used by ordinary Typst/PDF rendering. Glissade’s HTML, dev, and video exporters override source FPS settings with their command-line --fps. Use slide-number() when the rendered content should display its position in the deck.

slide-metadata.typslide options
#slide(
  id: "overview-title",
  title: "Overview title",
  autoplay: true,
  fps: 16,
)[
  #init(width: 70pt)
  #animate(width: 210pt, duration: .9)
  #wait(duration: .45)
  #cut(loop: true)
  // ...
  slide #slide-number()
]

Present and navigate

The HTML viewer schedules logical frames from elapsed time. If the browser renders more slowly than the selected FPS, it skips intermediate frames instead of slowing the animation. It still stops exactly at non-looping cuts. Loop cuts repeat their preceding segment until you continue.

InputAction
→ Page DownStart or continue; press rapidly or hold to step through keyframes. After 400 ms without advancing, the next press plays normally.
← Page UpReturn to the current or previous animation boundary.
SpacePlay or pause.
OOpen the slide overview and playback preferences.
FEnter fullscreen.
MouseClick the slide to continue when paused; double-click a playing animation to pause it.
TouchTap to play or pause, swipe left to continue, and swipe right to go back.

The overview can pause playback when the tab is hidden or when the window loses focus. These preferences are stored in the browser. Generated manifests may provide defaults with pauseWhenHidden and pauseWhenBlurred.

Export and preview

The command-line bridge compiles Typst, reads Glissade metadata, extracts SVG frames, and packages the browser runtime. Use dev while authoring and html when you want a portable presentation.

# Live editor
glissade --root . slides.typ dev --fps 12

# Self-contained HTML presentation
glissade --root . slides.typ html --fps 24 --title "My talk"

# MP4 video, split at every cut
glissade --root . slides.typ video --fps 24 --cut all

--root sets the Typst project root and is important when slides import files outside their own directory. Run glissade slides.typ html --help for the complete current option list.

OptionCommandsDefaultMeaning
--fpsall30Frames per second, for every slide.
--ppiall144Pixels per inch.
--cutallallWhich cuts to consider: all, scene, or none.
--titlehtmlTitle of the HTML presentation.
--progresshtmloffDisplay a progress bar.
--host, --portdev127.0.0.1, 8765Address of the live editor.
--formatvideomp4Output video format.

HTML output

HTML output embeds, minifies, gzip-compresses, and delta-optimizes SVG frames by default. Use --no-embed-frames for slides.html accompanied by its own slides.frames/ directory (serve this variant over HTTP), --no-compress-frames or --no-optimize-frames while inspecting generated assets, and --no-minify-svg while debugging SVG markup.

Video

Video export requires FFmpeg. Use --cut none for one video containing the complete deck, --cut scene for one file per slide, or --cut all for one file per presenter segment. MP4 output uses H.264 with a browser-compatible pixel format.

Video uses Typst raster frames. Browser morph and drawing interpolation are available in HTML and the playground.

Live editor and playground

The live editor watches images, fonts and common data files alongside Typst sources, and retains the previous preview when compilation fails. The playground supports Glissade decks with glissade-morph, semantic part markers and create; Touying and arbitrary local imports remain CLI workflows.
